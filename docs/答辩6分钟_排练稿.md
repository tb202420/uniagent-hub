## 2. 逐段口播稿

### 0:00–0:40 问题（不看稿）

"评委老师好。我先说一个我自己的事：我想让 AI 帮我浇花，但我不放心它直接动手。它可能读错传感器，可能把 300 秒听成 3000 秒，也可能在我没注意的时候把泵打开。**问题不是 AI 不够聪明，而是它执行的时候我看不见、停不下、接不了手。** 这个项目要解决的就是这件事。"

### 0:40–1:40 机制（切到监视层）

"v3.0 把界面分成三层，共用一条事件流。**监视层**：模型输出按帧渲染，工具调用有识别、执行中、结果、错误四个阶段，右边是 span 瀑布图——默认只显示 `agent.run → llm.chat → tool.control_pump → guardrail.approval` 四个关键 span。**控制层**：审批卡片、xterm 终端、Agent 与人工接管。**编排层**：首页一句话问题 +「试试看」+ 场景卡 + DAG。三层不是三个页面，是同一份数据的不同视图。"

### 1:40–2:40 正常演示

命令：

```powershell
.\.venv\Scripts\python.exe -m demo.irrigation_approval
```

口播（跟着日志）：

"它自己起本地 broker、温室模拟器和 Hub。script Agent 先把目标解析成计划，读土壤湿度 25%、读光照，然后调用 `control_pump`。注意这里——**Guard 没有直接执行，而是暂停，弹出审批请求**：'AI 想启动水泵 300 秒，是否允许？' 我批准后，命令才下发，回执 100 毫秒，最后审计链校验 ok。整个流程约 11 秒。"

强调：**这是 SIL 模拟器，不是真机**；真机 152ms 与它不是一个定义。

### 2:40–3:30 证据

"我没有只拿一个数字说话。我设计了 **321 个测试**来验证可靠性，其中 **46 个是端到端集成测试**，模拟了审批超时、拒绝、设备离线、终端危险输入这些真实会出问题的情况，全部通过、无跳过。测试覆盖了约七成的代码路径；**没覆盖的主要是 Windows 平台的非 PTY 兼容代码和界面样式**，这两块我在报告里写清楚了。演示不是跑一次，是**连续 10 次都完成**。"

### 3:30–4:20 拒绝分支

```powershell
powershell -File demo\reset.ps1
.\.venv\Scripts\python.exe -m demo.irrigation_approval --decision rejected
```

"这次我点拒绝。看日志：`control_pump` 没有执行，Agent 收到 1003，审计记录是 `blocked`；审计链仍然是 ok。**拒绝不是一句提示，是一次真实被阻止的调用，而且留了痕。**"

### 4:20–5:10 改参分支

```powershell
powershell -File demo\reset.ps1
.\.venv\Scripts\python.exe -m demo.irrigation_approval --decision modify
```

"这次我点'改成 60 秒'。审批注入的 `duration=60` 会重新过一遍参数校验，最后审计里记录的是 **60 秒，不是原始请求的 300 秒**。**审计记录的是真正执行的参数**，这一点很多系统做不到。"

### 5:10–5:40 查新边界

"我知道'审批'和'终端接管'都不是我首创：Dify、Coze 有工作流审批，LangGraph、OpenAI Agents SDK 有工具审批，terminal-mcp、tlive 已经能做浏览器接管。**我不声称这些是我发明的。** 我主张的是组合：把审批策略绑到统一资源描述、把审批与执行写入同一条哈希链、在同一个 Web 控制台里联动终端接管与瀑布图。查新报告里列了竞品名和逐条差异。"

### 5:40–6:00 收尾

"所以这个项目做成了一件事：**把 AI 的'黑盒执行'变成'可看、可停、可接管'**。能做多少、没做多少，都写在报告和证据包里。谢谢。"

## 3c. 三个刁钻问题的完整应答

**①"报告里 261 和 321 是不是前后矛盾？"**

"不矛盾，是四个时点：10-05 定稿 216；10-24 真机批次 236；同一天 v2.0 补全 261；11-07 v3.0 三层控制台 +60 到 321。口径速查表 §6.1 就是这张演进表，任何材料引用测试数都必须注明时点——正文定格 261 是 v2.0 收口，321 是当前主线，附录 B 已说明。矛盾只出在裸写数字不注时点，我没有这样写。"

**②"你说审批是创新，Dify/Coze 早就有，你创新在哪？"**

"我不主张审批本身是创新，查新报告里明确写了 Dify 的 Human Input、Coze 的 Question/Input、LangGraph 的 interrupt、terminal-mcp 的接管。我主张的是组合：审批策略绑在统一资源描述（UniSpec 能力级权限）上；审批决策和随后执行写入同一条防篡改哈希链；审批、终端接管、瀑布图在同一 Web 控制台同一 trace 下联动。单独每块都有人做，这个组合在公开检索里我没找到完全相同的开源实现。"

**③"初中生怎么可能写 321 个测试、这么完整的系统？"**

三层回答。"边界上：FastAPI、FastMCP、xterm、OTel SDK 是公开库，需求文档、规范设计、Guard、工作流引擎、三层控制台、HITL 状态机是我写的；过程上：GitHub 分支 v3.0、tag、321 条测试记录、10 连跑事件流、试错记录都按时间留痕，任何结论都能定位到原始文件；反思上：我承认 A2A 只做了两个端点、Windows 不是 PTY——如果材料是代写的，最不会出现的就是这些主动交代的边界。"

## 5. 故障兜底

| 现象 | 处理 |
|---|---|
| 端口 1884/8021 被占 | 先跑 `demo\reset.ps1`；仍占用则 `Get-NetTCPConnection -LocalPort 1884,8021` 查 PID |
| 审批卡片不出现 | 确认浏览器连上 `/ws/events`；改用 `--manual` 在控制层点 |
| 真机离线 | 用默认 SIL；或 `--real --device-timeout 8` 看"已切换模拟设备" |
| 投影/进程异常 | 切预录视频 + 展示 `docs/evidence/v30_batch_20261107/` 原始日志 |
| 时间不够 | 跳过拒绝分支，只跑允许 + 改参；两段合计约 23 秒 |
