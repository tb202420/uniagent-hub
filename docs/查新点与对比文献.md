## 查新点 1：基于设备端能力自描述的 MCP 工具自动发现

**表述**：检索中未见设备端以一份自描述文档（retain 发布）即可让平台零配置生成
MCP 工具、并实现"插上即被发现"的相同报道。

**本课题特征**：设备上电向 `register/<id>` 发布 retain UniSpec（七要素 + JSON Schema），
Hub 侧零行配置自动注册 3 个 MCP 工具（自动发现 0.23s）；同一契约在 Python 模拟器
与 ESP32 真机固件间逐字段对齐（回归测试防漂移）。

**对比文献**：
- [3] W3C WoT Thing Description 1.1 —— 静态"物描述"标准，面向 Web 互操作，无 MCP 工具映射与自动注册语义；
- [9] MCPAggregator（mcp-agent）—— 聚合发生在**服务端**（服务器名_工具名命名空间），设备端仍需各自实现服务器；
- [11] IoT-MCP —— LLM 与 IoT 桥接，设备能力预定义于框架侧，非设备自描述即插即用。

**建议检索词**：MCP tool discovery / device self-description / thing description MCP / zero-config tool registration

## 查新点 2：面向非技术用户的自然语言灌溉控制与分级确认

**表述**：检索中未见在自然语言控制物理设备的场景中，将"能力级权限 + 参数校验 +
写操作确认 + 高风险二次确认"作为可实验的分级确认机制并给出拦截率数据的相同报道。

**本课题特征**：Guard 管道把权限细化到**能力级**（同设备查询 read 放行/控制 write 拒绝）；
简易模式 UI 写操作强制确认卡片；命令注入与越权拦截率 100%（错误码 1003/1007 可检索）。

**对比文献**：
- [1] JieGou MCP 安全危机（30+ CVE / 38% 无认证）—— 指出生态缺认证，未给出能力级分级确认机制与实验；
- [2] MCP 官方入门 —— 协议本身不含权限/确认层，安全留给实现方；
- [5] MCP stdio 配置注入攻击链 —— 聚焦注入路径与加固清单，无分级确认的用户侧实验。

**建议检索词**：MCP permission model / capability-level authorization / human-in-the-loop confirmation IoT / natural language device control safety

## 查新点 3：低配离线条件下脚本 Agent 保底的安全工具调用

**表述**：检索中未见"原生工具调用 → 提示词计划 → 确定性脚本"三级降级链在 4GB 级、
无稳定网络设备上保证 Agent 任务不中断的相同报道。

**本课题特征**：三级降级链任何一级失败自动回退并如实告警；本地量化模型
（3-bit，11GB）温度 0.0 对照实验：数值转述保真 0/5 → 4/5；断网（-Offline）
模式下核心演示链路完整可跑。

**对比文献**：
- [8] FastMCP 4 双协议协商 —— 解决协议兼容，不解决无模型/离线环境的任务兜底；
- [10] mcporter —— CLI 与 MCP 代码生成方向，无降级链与离线可用性主张；
- [11] IoT-MCP —— 依赖网关侧算力与连接，未覆盖离线降级。

**建议检索词**：LLM agent fallback / deterministic agent offline / tool call reliability low-resource / degradation chain agent
