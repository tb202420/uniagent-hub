### 脚本工作流（1:00–1:40，40s）

**操作**：①号终端继续观察同一条命令的输出；工作流执行时**切到 ④号空调模拟器窗口**。

**画面关键行**：
```
1. ✓ 31.1 (0ms)                                   ← IoT 传感器，MQTT 状态缓存
2. 温度 31.1°C > 28°C → 触发 office_cooling：✓ ... ← 一次调用完成 3 步闭环

```

**讲解词**：
> "温度 31 度超过阈值 28，Agent 触发一次 `run_workflow` —— **它只发了这一次调用**，
> 工作流引擎在内部完成测温 → 查天气 → 开空调，包括拓扑排序、数据管道（温度减 2 度传给空调）、
> 条件判断，每一步仍逐个过 Guard。请在**右下角空调窗口**确认 —— 设备真的收到了命令。"

### ESP32 温室灌溉（模拟器）（1:40–2:40，60s）★ 核心亮点

**操作**：
1. ①号终端运行**预先粘贴**的触发命令（等同 `tools/call run_workflow {"name":"smart_irrigation"}`）；
2. 工作流执行时切到 **③号温室模拟器窗口**看注册与回执日志；
3. 观察模拟器日志中的土壤湿度回升（浇水物理行为）。

**画面关键行**：
```
①号终端：
   s1 get_soil_moisture   → 25%（< 30 阈值）  0ms
   s2 get_light_intensity → 12123.5 lux       0ms
   s3 control_pump(action=on, duration=300) → 回执确认（100ms）✓
③号模拟器窗口：
   [sim_irrigation] 已注册 UniSpec(保留) -> ...register/irrigation_01
   [sim_irrigation] .../state <- {"soil_moisture":25.4,...,"pump":"off"}   ← 30s 周期上报
   [sim_irrigation] 命令 {'action':'on',...} -> 水泵 on（300s 后自动停止）   ← 土壤湿度回升
```

**讲解词（分两段）**：
> "刚才都是模拟器和软件资源；现在接的是一个**温室灌溉节点**：这里用 Python MQTT
> **模拟器**复现真实 ESP32 节点的传感器读数与水泵回执（土壤湿度、光照强度、水泵开关）。
> 注意 —— 设备端只发布了一份 UniSpec 描述（retain 消息），
> 平台**零配置**就自动发现了它并生成三个工具。
> 现在土壤湿度 25%，低于 30 的阈值；工作流判断条件满足，自动开泵浇水 ——
> **一次 run_workflow 调用，1.30 秒完成读土壤、判断、开泵的完整闭环**，
> 写操作有 QoS1 回执确认、有时长上限，全程过 Guard。"

> "这个场景是我上一届'智慧生态系统'项目做过的：当时每接一个传感器都要在平台侧逐个配置；
> 这一次，设备发布一份描述即可用 —— **这就是统一规范在异构节点接入上的价值**。"

### 安全拦截（2:40–3:30，50s）

**命令**（①号终端）：

```powershell
python -m agent.demo_agent --url http://127.0.0.1:8020
```

**画面关键行（依次出现）**：
```
[4] ✗ [1007] 参数 pattern 含非法字符（注入防护拦截）: 'x; rm -rf /'
[5] ✗ [1003] 权限不足: 需要 write，当前 read
    对比 ✓ {"action": "on", ...}          ← 同一设备 read 权限查询是放行的
[6] 第 2/3 次 ✗ [1004] 超出速率限制 1/s
```

**讲解词**：
> "平台的安全不是靠提示词约束模型，而是**内建在网关里的强制管道**，对 LLM 和脚本一视同仁：
> **命令注入**在参数校验阶段被拦截（1007），命令根本没有执行；
> **越权调用**被能力级权限拒绝（1003），但同一设备的只读查询放行；
> **限流**在连续快速调用时触发（1004）。
> 这些被拦截的调用全部留下完整审计记录，还带 Schema 签名与哈希链 ——
> 工具描述被篡改会被拒绝，审计记录被篡改会被定位。第七段审计界面可以看到。"

## 附：故障速查（录制中出问题的处理）

| 现象 | 处置 |
|---|---|
| 温度 ≤ 28°C，工作流不触发 | 关掉 sim_temp 窗口，重跑 `python -m adapters.mqtt_adapter.simulator --init-temp 31` |
| 温室模拟器未上线 / tools/list 缺硬件工具 | 重启 `sim_esp32_greenhouse --init-soil 25`；确认 retain 注册消息（约 0.23s 自动重新发现） |
| 泵不启动 | 检查模拟器进程与初始土壤湿度参数（`--init-soil 25`，<30 才触发） |
| 回执超时误报失败 | 已放宽至 3s + 幂等重试；仍失败则改播 `03b_esp32_irrigation.mp4` 兜底 |
| `get_weather` 现场卡 4-5s | 预热已失效（超 300s），重跑 `python -m scripts.demo_warmup --url http://127.0.0.1:8020` |
| 公共 broker 抖动 | 改用 `-Offline` 重启（本地 amqtt + Mock API）；温室模拟器同步切到本地 broker 后重录该段 |
| 端口被占用 | 启动脚本会直接报出占用端口与查看命令；关闭占用进程或改用 `-Port 8030` |
| 整机故障 | 播放 `demo_fallback/01_full_demo.mp4` |
