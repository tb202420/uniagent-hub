## 一、录制前准备（录制前 20 分钟）

### 1.1 本地 Ollama（必须提前预热，已实测）

```powershell
# 1) 启动服务。默认 11434；若被系统排除范围占用（本机命中 11346–11445）：
#    $env:OLLAMA_HOST = '127.0.0.1:11500'
#    & 'C:\Users\admin\AppData\Local\Programs\Ollama\ollama.exe' serve
#    排查：netsh int ipv4 show excludedportrange protocol=tcp

# 2) 设置项目访问地址（与上一步端口一致）
$env:OLLAMA_BASE = 'http://127.0.0.1:11500'   # 未被占用时写 http://localhost:11434

# 3) 预热模型（冷加载实测 90.5s，必须提前做；完成后常驻显存 11.05GB，ctx=16384）
.\.venv\Scripts\python.exe -m scripts.ollama_warmup --model gemma4local:latest --num-ctx 16384
```

- 关闭 Ollama 桌面版**自动更新**（实测后台更新会重启服务、卸载模型）；
- 预热输出应出现：`预热完成 …（num_ctx=16384，keep_alive=-1）` 与 `已常驻：ctx=16384 显存占用 11.05 GB`。

### 1.2 设备双方案切换（同一条命令骨架）

| | 方案 A：真机实测（HIL） | 方案 B：模拟器（SIL，默认） |
|---|---|---|
| 前置 | ESP32-S3 上电、连本地网络，能连 `mqtt://127.0.0.1:1884` | 无（脚本自动起模拟器，初始土壤 25%） |
| 命令 | `.\.venv\Scripts\python.exe -m demo.irrigation_approval --agent ollama --real --device-timeout 8` | `.\.venv\Scripts\python.exe -m demo.irrigation_approval --agent ollama` |
| 真机离线时 | 自动打印「已切换模拟设备（SIL 兜底）」并继续（**画面如实标注，不冒充 HIL**） | — |
| 回执口径 | 真机命令→回执 **152ms**（2026-10-24 证据；如现场复测以现场为准） | 写回执 **100–141ms（SIL）** |
| 讲解区别 | 强调"命令真的下到 ESP32，水泵继电器动作" | 强调"协议细节如实复现（retain 注册/QoS1 回执/时长上限），真机口径另列" |

> 推荐：**视频主线用方案 B（零硬件风险），方案 A 作为 30 秒加演**——真机在线则切 A 录一段回执特写；
> 两段都录，剪辑时按真机是否稳定二选一（原始录屏原则：只整段取舍，不做拼接）。

### 1.3 三层控制台窗口布局（浏览器 + 终端，2×2）

```
┌──────────────────────────────┬──────────────────────────────┐
│ ① 浏览器：三层控制台 /spa/    │ ② 演示终端（主舞台，≥16pt）  │
│    监视层：四阶段状态条+瀑布图 │    python -m demo.irrigation_ │
│    控制层：审批卡片/终端接管   │    approval --agent ollama    │
├──────────────────────────────┼──────────────────────────────┤
│ ③ 温室设备窗口（SIL 模拟器日志 │ ④ 审计面板（可后开）          │
│    或方案 A 真机串口监视器）   │    :18080/ 审计红色高亮        │
└──────────────────────────────┴──────────────────────────────┘
```

- 控制台首页（编排层）是开场画面：「我想让 AI 帮我浇花，但我不放心它直接动手」+「试试看」；
- 审批卡片出现时停留讲解（允许 / 拒绝 / 改成 60 秒三个按钮入镜）；
- 分辨率 1920×1080、30fps；只录麦克风；关闭系统通知与专注助手。

## 二、分镜与讲解（2 分钟参赛版 · 主线）

| 时间轴 | 时长 | 画面 | 操作 / 命令 |
|---|---|---|---|
| 0:00–0:20 | 20s | ① 控制台首页（编排层） | 开场：「让 AI 帮忙浇花但不放心它直接动手」——先问、再批、后执行 |
| 0:20–0:45 | 25s | ① 监视层 + ② 终端 | 回车运行 `--agent ollama`；tools/list 出现 14 个工具（演示档）；说明"背后的模型是本地部署的 Gemma 量化版，只做决策，动手必须过审批" |
| 0:45–1:20 | 35s | ① 审批卡片 + 监视层四阶段 | 模型调 `control_pump(300s)` → **审批卡片弹出** → 点「允许」→ `identified→executing→result` + 瀑布图 4 个关键 span；②终端出现模型总结（如实复述土壤湿度） |
| 1:20–1:40 | 20s | ① 控制层 + ④ 审计 | 二选一快速分支：**拒绝**（审计 blocked/1003，模型如实说"审批未通过"）或**改成 60 秒**（审计 duration=60）；审计红色高亮入镜 |
| 1:40–2:00 | 20s | ④ 审计页 + ① | 收口：审计哈希链 ok、321 项测试、真机/模拟器口径各归其位（方案 A 则此处放 152ms 回执特写）；结束 |

**讲解要点（逐句，背熟数字口径）**：

1. "模型的每一步决策都先经过平台的 Guard 管道；`control_pump` 这种写操作，**没有人的批准不会执行**。"
2. "审批决策会写进审计哈希链——拒绝（1003）和超时复用同一错误码表，没有为演示改过代码。"
3. "本地 3-bit 量化模型有 ±1 度的数值转述误差——所以平台规则要求它**原样复述工具返回的数值**，演示里可以看到它如实报告 24.2%。"
4. "这台模型是本地部署的（11GB 权重常驻显存），全程不依赖云端 API——断网也能演示。"

## 附二：故障速查（录制中出问题的处理）

| 现象 | 处置 |
|---|---|
| `ollama serve` 起不来 / 11434 绑定失败 | 本机 11346–11445 为系统排除端口：`$env:OLLAMA_HOST='127.0.0.1:11500'` 重启 serve；`OLLAMA_BASE` 同步改 11500 |
| 模型决策明显变慢 / 首次卡住 | 未预热：先跑 `scripts/ollama_warmup`；确认 `keep_alive=-1` 常驻 |
| 模型不调用工具（LLM 退化） | 平台三级降级：现场改跑 `--agent script`（默认确定性脚本），并口头说明"平台不依赖 LLM 可靠性" |
| 审批卡片不出现 | 确认 Hub v3.0（`/healthz`）；浏览器已连 `/ws/events`；`HUB_APPROVAL_TOOLS=control_pump` 已由演示脚本设置 |
| 真机未上线 | 方案 A 自动 SIL 兜底（画面如实标注）；或切方案 B 重录该段 |
| 端口 1884/8021 被占 | `powershell -File demo\reset.ps1` 后重试 |
