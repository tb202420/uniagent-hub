## 附件三：SIL / HIL 对照说明

**SIL（Software-in-the-Loop，软件在环）**：用 Python 程序模拟设备行为（本项目为
`sim_esp32_greenhouse.py`），验证协议契约、状态机、写回执与工作流闭环。它回答
"协议和逻辑对不对"，不回答"真实电路在温漂、电磁干扰、断电时还稳不稳"。

**HIL（Hardware-in-the-Loop，硬件在环）**：把真实硬件接入闭环（本项目为 USB 摄像头、
智能插座、手机传感器、PC 监控 4 类），验证"协议在仿真里跑通后，真插上还行不行"。

**为什么先用 SIL 验证**：温室节点涉及水泵、继电器与土壤传感器；先用 SIL 把契约、
条件判断、时长钳位（1–600s）、自动停泵、写回执跑通，再上真机，能快速定位问题在
"协议/逻辑"还是"电路/链路"。SIL 可重复、可注入故障（如离线、非法命令），适合
作为日常回归；真机则用于验证物理执行链路。

**真机数据采集条件（2026-10-24，`real_device_e2e_20261024`）**：ESP32-S3 烧录本项目
固件，MQTT 经同一 broker；命令→回执往返 5 轮均值 **152ms**（min 100 / max 209），
经 Guard 全链路 **100ms**，`duration=5s` 自动停泵实测 **5.1s**；传感器未接线部分按契约
缺省，因此温室闭环仍以 SIL 为主。**本次 v3.0 未重新测真机**，SIL 的 100–141ms
不得写成真机 152ms。

**一句话**：SIL 证明"逻辑对"，HIL 证明"接上真设备也对"，两者数字定义不同、不能混用。
