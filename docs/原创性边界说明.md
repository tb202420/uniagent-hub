## 3. 明确没有做的部分（避免夸大）

- **A2A 只做任务委派 + 状态查询**：没有实现完整任务生命周期、流式事件、多轮协商。
- **MHS 只做理念映射**：用 `protocol_bindings.hardware_side=MHS-compatible` 表达
  硬件侧位置，没有实现 MHS 的完整规范栈。
- **Windows 没有 PTY**：交互终端在 Windows 是持久管道会话；POSIX 才是 `pty`。
- **OTel 没有自建 Collector**：配置 `HUB_OTEL_ENDPOINT` 时才向外部 Collector 导出；
  默认使用本地 span 记录器 + 无导出器 Provider。
- **Tauri 只到"外壳已编译验证"**：NSIS 打包与窗口运行未实测。

## 4. 一句话回答

> "协议接入用公开的 FastMCP/FastAPI/OTel SDK，硬件用公开的 PlatformIO 生态；
> UniSpec 字段设计、Guard 审批状态机、事件总线、三层控制台联动、A2A 克制实现
> 和演示闭环是我自己写的，因为 v2.0 在真实使用中暴露了'AI 执行过程不可见'
> 的问题。"
